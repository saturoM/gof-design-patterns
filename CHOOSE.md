# Як обрати патерн (анкета)

Не починай з назви патерна. Почни з **болю**, відповідай на питання по черзі.

## Крок 0 — яка полиця?

1. Болить **народження** обʼєкта (хто робить `new`, який тип, як зібрати)? → **Creational**
2. Болить **структура** (обгортка, стик несумісного, дерево частин)? → **Structural**
3. Болить **поведінка в часі** (статуси, алгоритми, хто кого кличе)? → **Behavioral**

Якщо підходять дві полиці — спочатку закрий ту, де біль сильніший. Якщо сумнів — бери **простіший** варіант без патерна.

---

## Creational (пройдено частково)

| Питання | Якщо так → |
|---|---|
| Має бути **рівно один** екземпляр на процес (логер, конфиг процесу)? | **Singleton** (у Nest часто DI «один інстанс») |
| Треба вибрати **який клас** створити (напр. on-ramp vs off-ramp)? | **Factory Method** |
| Треба створити **ціле сімейство** сумісних речей разом? | **Abstract Factory** *(ще буде)* |
| Збірка **складна**: багато кроків/полів (FX, комісії, дефолти)? | **Builder** *(ще буде)* |
| Дешевше **клонувати** готовий зразок, ніж збирати з нуля? | **Prototype** *(ще буде)* |

### Швидкі «ні»

- Багато інвойсів / правда між рестартами → не Singleton, а **БД (SoT)**
- Ховаєш поля при збірці → це не Factory Method, дивись **Builder**
- Один простий тип і один `new` → часто **без патерна**
