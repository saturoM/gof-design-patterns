# Singleton · Creational №1

**Статус:** ✅ залік 2026-09-11

## Картка (5 рядків)

1. Один екземпляр на **процес** + спільний доступ.
2. Як один холодильник на квартиру.
3. Мінус: схоже на глобальну змінну, важко тестувати / підмінити.
4. У Nest краще **DI**, ніж ручний `getInstance()`.
5. Спільна правда на весь світ → **БД (SoT)**, не Singleton.

## Де так / де ні

| | |
|---|---|
| **Ок (обережно)** | Логер, конфиг процесу, інфра «на цей процес» — часто через DI як один інстанс |
| **Лише виглядає** | «Один Postgres», один рядок налаштувань у БД, `export default new Service()` |
| **Краще не треба** | Invoice, поточний юзер, лічильник грошей, кеш як єдина правда |

## Тести (пройдено)

1. Singleton гарантує що? → **один на процес** (не на весь світ).
2. Invoice як Singleton? → **ні** (багато інвойсів, SoT у Postgres).
3. Чому DI замість `getInstance()`? → **легше підставити мок у тесті**.

## Поліція болю

**Створити** — контролюємо *скільки* екземплярів народжується і *хто* їх віддає.
